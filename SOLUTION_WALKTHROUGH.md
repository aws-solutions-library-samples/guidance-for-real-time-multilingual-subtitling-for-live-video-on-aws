# Solution Walk-through: AI-Powered Live Multilingual Subtitling

## 2. Solution Walk-through [Architecture Page]

Let's walk through how this solution works end-to-end, starting with live stream ingestion and culminating in AI-powered subtitle delivery across 20 languages.

[Click] The workflow begins when a live stream is pushed to AWS Elemental MediaConnect. This can be any input which Elemental MediaConnect supports but in this scenario we used input as srt-listener on port 3088. MediaConnect acts as our reliable transport service, ensuring high-quality video delivery with built-in redundancy and monitoring capabilities.

From MediaConnect, we create two distinct output paths to handle both video processing and subtitle generation simultaneously. [Click] The first output is directed to [Click] AWS Elemental MediaLive for stream transcoding into Adaptive Bitrate, or ABR format. This ensures viewers receive the optimal video quality based on their device capabilities and network conditions. [Click] MediaLive also pre-configures 20 caption slots for multilingual subtitle tracks, which act as containers ready to be filled with translated subtitles in real-time.

[Click] The second output takes a different path focused on subtitle generation. [Click] This RTP audio stream is sent to a Network Load Balancer with a static Elastic IP address, which routes traffic to Amazon ECS Fargate tasks running Docker containers. Unlike traditional EC2-based architectures, we use ECS Fargate for serverless, scalable subtitle processing. The Fargate task runs a Docker container with Node.js and FFmpeg, providing 4 vCPUs and 8 GB of RAM for high-performance audio processing. This approach eliminates server management overhead while providing built-in health checks and automatic scaling. [Click]

[Click] The ECS container extracts the audio stream using FFmpeg and pipes it to Amazon Transcribe Streaming API for real-time speech-to-text conversion. Transcribe provides highly accurate transcription with support for custom vocabularies, which is particularly valuable for industry-specific terminology or proper nouns that frequently appear in your content. For example, in sports broadcasts, player names and technical terms are pre-configured to ensure 100% accuracy. It also provides a custom language model capability, allowing you to train domain-specific speech-to-text models. [Click]

Once we have the transcribed text, [Click] it's passed to Amazon Bedrock's Nova Foundation Models for translation. This is where the magic happens – Nova's advanced language models provide nuanced, context-aware translations that maintain the meaning and tone of the original content across multiple target languages. In this scenario we used Amazon Nova Micro, which is a model focused on ultra-low latency and cost. It provided fast translations while also delivering consistent results across all 20 supported languages. The translation engine doesn't just convert words – it understands context, idioms, and emotional tone, ensuring that a commentator's excitement in English translates to equally enthusiastic subtitles in German, Spanish, Korean, or any other target language. [Click]

[Click] Now, here's where AI agents come into play. A unique feature of this solution is the Strands Agent-powered chatbot running on AWS Lambda. This AI agent provides intelligent, conversational management of subtitle operations without requiring technical knowledge. Operators can use natural language commands like "Add Korean language" and the agent automatically activates the Korean translation track. Or they can ask "Why is Spanish subtitle delayed?" and the agent will diagnose ECS task health and DynamoDB latency in real-time. [Click]

[Click] Instead of requiring MediaLive channel restarts to change languages, the agent uses a DynamoDB-backed language configuration table to enable or disable languages on-the-fly. This table stores information about all 20 pre-configured languages including their active status, segment IDs, and translation settings. The agent also exposes RESTful endpoints for programmatic control – GET /languages to list all languages, POST /languages to add new ones, and DELETE to remove them. This dynamic language management means you can respond to audience demands in real-time during live events. [Click]

The transcription and translation output is then processed and segmented into time-synchronized subtitle segments, [Click] which are stored in Amazon DynamoDB. DynamoDB's millisecond latency and automatic scaling make it perfect for handling the real-time nature of live subtitle delivery, even during high-traffic events. The table uses a Global Secondary Index for efficient language-specific queries, and includes a Time-To-Live attribute that automatically expires old subtitle data after one hour, keeping storage costs minimal. [Click]

Meanwhile, the ABR-transcoded stream from MediaLive is delivered [Click] to AWS Elemental MediaPackage. At this stage, we introduce AWS Lambda functions that add timestamps to blank WebVTT subtitle files, enabling dynamic subtitle insertion. MediaPackage packages the live stream into HLS format with 2-second segments, creating separate tracks for each of the 20 pre-configured languages. [Click]

[Click] For content delivery, we leverage Amazon CloudFront as our global content delivery network. CloudFront intelligently routes different types of requests – media file requests like .m3u8 and .ts files go directly to MediaPackage for optimal video delivery performance, leveraging CloudFront's 400-plus edge locations worldwide to reduce latency for global audiences. [Click]

However, subtitle WebVTT file requests follow a more sophisticated path. [Click] These requests are routed through Amazon API Gateway to a Lambda function that performs real-time subtitle assembly. Here's how it works: This Lambda function first fetches the time-stamped subtitle template from MediaPackage, which contains placeholders and timing information. Then it retrieves the appropriate translated subtitles from DynamoDB based on the requested language code and timestamp range using the Global Secondary Index. Finally, it dynamically inserts the correct translated subtitles into the WebVTT file before returning it to the client. [Click]

[Click] We take this one step further with Lambda@Edge functions. These functions run at CloudFront edge locations, processing subtitle requests closer to viewers. This edge processing reduces subtitle assembly latency to under 100 milliseconds worldwide and offloads 90% of traffic from MediaPackage and DynamoDB. The result is global-scale subtitle delivery with consistent performance. [Click]

[Click] Finally, viewers access the live stream through a unique web player interface featuring a 2x2 video grid layout. Unlike traditional single-player interfaces, this solution displays 4 independent video players on a single screen, each capable of showing a different language simultaneously. For example, Screen 1 might show English subtitles, Screen 2 shows German, Screen 3 shows Spanish, and Screen 4 shows Italian – all playing the same live video in perfect synchronization. This is particularly valuable for broadcasters who want to compare translation quality across languages in real-time, or demonstrate multilingual capabilities to stakeholders without switching streams. [Click]

[Click] Each video player has its own language selector, and the interface includes a draggable, resizable AI chatbot panel with five tabs. The Chat tab provides conversational AI for natural language commands. The Languages tab offers visual language management with simple checkboxes to toggle any of the 20 languages on or off with a single click. The Translation tab lets you select the translation style – Energetic for sports commentary, Formal for news broadcasts, Casual for entertainment shows, or Technical for specialized content. The Dictionary tab manages custom vocabulary in real-time, allowing you to add domain-specific terms or upload CSV vocabulary files. And the Search tab provides subtitle history and analytics, letting you search past subtitles by keyword or timestamp, export transcripts for archival, or submit translation quality feedback. [Click]

[Click] At the bottom of the interface, a visual status bar displays the current translation style with animated color transitions – red for Energetic, blue for Formal, green for Casual, and purple for Technical. This provides immediate visual feedback about the tone being used for translations across all active languages. [Click]

This architecture ensures that subtitles are always synchronized with the video content while providing the flexibility to serve 20 languages simultaneously without duplicating video streams. [Click] The integration of AI agents transforms what was once a complex, manual operational task into a conversational, intelligent workflow. By leveraging AWS AI services including Transcribe and Bedrock, serverless compute with ECS Fargate and Lambda@Edge, and intelligent agents powered by the Strands framework, this solution delivers enterprise-grade live subtitling with unprecedented flexibility and cost efficiency. Real-world performance metrics show end-to-end latency of just 2 to 4 seconds from video ingest to subtitle display, transcription accuracy above 95% with custom vocabulary, translation quality of 98% semantic equivalence using Nova Micro, and the ability to scale to over one million concurrent viewers with CloudFront – all at 70% lower operational cost compared to traditional EC2-based alternatives. [Click]
